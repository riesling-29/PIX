## 체크하는 방법

각 제목은 전체 알고리즘 이름보다 **이번에 판단할 잔여 확장·검증 범위**를 드러내도록 적었다. 제목 아래 원래 업무 질문도 유지했다. 기존 기능 전체를 폐기하자는 투표가 아니다.

선생님은 각 항목에서 `선생님: 필요` 또는 `선생님: 불필요` 중 **하나만** 체크하면 된다. 둘 다 빈칸이면 미판정이고, 둘 다 체크되면 충돌이므로 판정을 보류한다. 필요하다고 생각하는 세부 범위가 다르면 해당 항목 아래 자유롭게 메모를 추가하면 된다.

Vera 칸은 초기 판단을 미리 체크했다. “불필요”는 현재 목표에서 **표기한 잔여 확장을 권하지 않는다**는 의견이며 이미 존재하는 계산의 삭제나 해당 분야 전체의 폐기를 뜻하지 않는다. “필요”는 가능성·정확성·일정 보장이 아니라 추가 설계/검증 대상에 유지하자는 판단이다.

| Vera | 선생님 | 공동 처리 |
|---|---|---|
| 필요 | 필요 | 잔여 구현 대상으로 확정. 먼저 범위·인수 조건을 정하고 해당 범주에 맞춰 구현/검증 |
| 불필요 | 불필요 | 표기한 잔여 개발 범위에서 제외. 제외 이유를 보존 |
| 필요 | 불필요 | 추가 논의. 구현·폐기 확정하지 않음 |
| 불필요 | 필요 | 추가 논의. 구현·폐기 확정하지 않음 |
| 어느 쪽이든 미응답 또는 이중 체크 | — | 판정 대기. 빈칸을 불필요로 해석하지 않음 |

**최초 작성 시점에는 공동 확정이 0개였다.** 이후 회신의 필요·불필요 표와 조건을 대조한 현재 처리는 위 세부 설계와 추적표를 따른다. 체크박스는 자동 판정 프로그램이 아니며, 조건부 의견이나 미응답을 무조건적인 구현·제외로 해석하지 않는다.

이전 gap에는 W4 전의 문장이 섞여 있다. 최신 구현을 반영해 reset/inhibitor, sequence tensor, time/group split, held-out 평가, 다중검정, timed PN, 최대 분해, 정정/checkpoint를 다시 처음부터 개발하는 것으로 적지 않았다.

**중복 개념 주의:** PM4Py와 OCPA에 공통인 기능도 비교표 ID를 보존해 별도 투표한다. 두 행 모두 필요해도 같은 계산을 두 번 만들지는 않는다. 행별 입력/profile 요구를 통합 설계하고 검증만 구분한다. 복합행에서 일부만 필요하면 “필요”에 체크하고 범위를 메모한다.

**유효 범위와 재검토:** 현재 코드·목표에 대한 1차 의견이다. 실제 사용처가 드러나거나, 이미 충족된 잔여로 확인되거나, 작은 반례로 선언한 계산이 깨지거나, 지원 조건/제품 책임이 달라지면 범주와 Vera 표를 다시 검토한다. 전체 구현 공수와 성공률은 알 수 없음이다.
