# PIX 잔여 기능 세부 설계

작성: 2026-09-18. 상태: **설계 초안·범위 합의 반영. 구현/테스트 완료 보고가 아님**.

후속 구현: [입출력·계산 기반 구현 기록](../reports/2026-09-18_PIX_RESIDUAL_CORE_IMPLEMENTATION.md)에 실제 변경과 테스트를 별도로 기록했다. 이 설계의 모든 항목이 완료된 것은 아니다.

## 1. 협의 상태와 문서의 효력

[공동 체크리스트](2026-09-18_PIX_REMAINING_177_JOINT_REVIEW_CHECKLIST.md)의 작성 시점 표시를 다시 집계하면 양측 필요 158, 양측 불필요 12, 불일치 5, 빈칸 2로 총 177개다. n-gram은 대화에서 설계 포함을 명시해 필요로 반영했다. 이 수치는 투표 상태이며 개발 작업 수나 완성률이 아니다.

모든 항목의 협의가 끝난 것은 아니다. 다만 미판정 항목이 다른 영역 설계를 막지는 않는다. **후속 명시 결정: “수집은 Agent, 계산은 PIX”를 확정된 책임 원칙으로 적용한다.** HTTP·GitHub·브라우저·OS 수집 모두에 적용하며, 수집 후보의 필요 표가 PIX 수집기 구현을 뜻하지 않는다. 아래 숫자는 체크리스트의 표와 조건을 분류한 이력이며 후속 결정은 추적표의 처리 설명에 별도로 반영한다.

## 2. 구조와 공통 결과 계약

업무 흐름은 **외부 자료/Agent 이벤트 → 원본 보존 입력 → 분석 단위와 순서 선택 → 계산 → 근거를 포함한 결과 → 화면/Schumpeter**다. CaseLog와 canonical OCEL을 유지한다. Case-centric 계산 전에 모든 로그를 OCEL로 강제 변환하지 않는다. OCEL을 case로 투영할 때는 객체 공유·속성·원본 ID와 정보 손실을 설명한다.

PIX는 발견·적합성·성능·통계·모델 계산을 소유한다. PM4Py/OCPA의 계산 호출로 대체하지 않는다. 수집의 실행 주체는 Agent이며 Schumpeter는 수집 작업을 연결·관리한다. Graphviz 등 표현용 의존성과 일반 수치 solver의 사용 여부는 계산 책임과 별도로 명시한다. Schumpeter는 모델/API 선택, 작업 전달, 지속 저장과 운영 정책을 소유하는 구성을 제안한다.

확인한 기존 `ComputationResult`에는 operator 판본, source digest, spec, status, value, issues, computation ID와 부모 계산 ID가 있다. 이를 재사용하고 새 상태 체계를 중복 생성하지 않는다.

| 계약 | 설계 규칙 |
| --- | --- |
| 입력 | 입력 종류·스키마 판본·원본 identity를 보존. 지원 불가능한 구조는 묵시적으로 단순화하지 않음 |
| 모집단 | case/object/execution/event/발생 구간을 구분. 필터·시간창·객체형·분모를 결과에 기록 |
| 시간 | 시작/완료/lifecycle/달력시간/업무시간, 시각 동률, 시간대와 열린 관측을 명시 |
| 정의 | 지표 공식·variant·비용·정규화·순서·동치 정의를 버전화된 spec으로 식별 |
| 결과 | computed/partial/unavailable/invalid_input을 재사용. 탐색 중단을 불가능 또는 부적합으로 표시하지 않음 |
| 근거 | 숫자·모델·선택 결과에서 원본 ID 또는 재현 가능한 근거 위치로 연결. 생략 한도를 표시 |
| 변경 | 기존 기본값의 의미를 바꾸면 새 profile로 제공하거나 변경 설명·호환 검증을 동반 |
| 지원 한계 | 유한/무한, 정확/근사, 표본/전수, 시간·메모리 제한과 종료 이유를 구별 |

이 문서는 새 표준이나 새 라이브러리 판본 조사가 아니라 로컬 요구·계약에 대한 설계다. 기존 평가가 고정한 참조 판본을 기준으로 구현하며, 이후 upstream 변경은 별도 차이 검토로 처리한다.

## 3. 작업 묶음과 의존 순서

각 묶음 안에서도 `의미와 작은 예제 → 기존 구현 차이 확인 → 구현 → 검증 → 사용자 샘플 검토` 순서로 진행한다. 공통 기능은 PM/OC ID가 달라도 한 번 구현하고 각 profile의 검증을 나눈다.

| 묶음 | 담당 내용 | 선행 조건 |
| --- | --- | --- |
| R01 | 입력·출력·mapping·공개 진입점 | 공통 계약 |
| R02 | Case 필터·시간·통계 | R01의 입력 의미 |
| R03 | Object 분석 단위·관계·변환·필터 | R01, 필요한 R02 시간 규칙 |
| R04 | Case 모델 표현·변환·축약·정당성 | R01 모델 교환 |
| R05 | Case 발견 | R02, 해당 R04 모델 |
| R06 | Case 적합성·alignment | R04, 비용·완료 정의 |
| R07 | OC 발견·모델·적합성·성능 | R03, 재사용하는 R04/R06 계산 |
| R08 | Feature·학습·n-gram·검정 | R02/R03 분석 단위 |
| R09 | 자원·조직 지표 | R02 시간·분모 |
| R10 | 시뮬레이션·확률 언어 | R04/R07 실행 의미, R02 관측 시간 |

첫 구현 묶음은 **R01의 출력·mapping 중 확정 범위와 R02의 시간·집계 정의**로 제안한다. n-gram은 이 정의가 필요한 최소 범위만 갖춰지면 R08의 독립 묶음으로 앞당길 수 있다. R04 전체 완료를 기다릴 필요는 없다. R14는 PIX 경계 계약부터 설계하고 Hub 자체 개발과 구분한다. 일정·공수·완료 날짜는 미측정이다.

## 4. R01 — 입력·출력·mapping·진입점

**업무 결과:** 가져온 자료를 다른 도구로 전달하고, 동일한 모델과 로그를 재현 가능한 방법으로 다시 읽는다.

입력은 CaseLog/canonical OCEL/명시 지원 모델이고, 출력은 선택한 XES·OCEL profile·CSV/Parquet bundle·DFG·BPMN·bytes다. 파일 확장자만으로 호환성을 선언하지 않고 profile별로 표현 가능한 속성·관계·시각·metadata를 정리한다. XES는 trace/event/global/classifier 등 지원 범위를 고정하고 gzip은 동일한 내용의 운송 방식으로 다룬다. OCEL 하위 형식에서 표현할 수 없는 이력·qualifier·관계는 손실 목록에 남긴다. 기본 손실 정책은 조용한 삭제가 아닌 거부 또는 명시 동의 방식으로 제안한다.

열 mapping은 case/activity/time 및 객체형·객체 ID를 명시한다. 빈 case, 결측 시각, 중복 ID, nested 속성, 이름 충돌을 구별한다. 문자열 parser는 작은 검산용 언어를 우선하며 임의 실행 기능을 넣지 않는다. POWL parser는 문법·진단·왕복 보존에 필요한 실제 변경 규모를 먼저 확인하고 비용 조건을 충족했다고 임의 판단하지 않는다. CLI는 같은 공개 API를 호출하고 결과·오류·종료 코드를 계약으로 고정한다.

**검증·인수:** reader/writer를 서로만 대조하지 않고 수작업 기대 문서와 독립 fixture도 사용한다. 빈 로그, Unicode, 타입·metadata·동시각·압축·bytes 왕복, 손실 허용/거부, 실환경 Parquet 의존성 설치·실행을 검증한다. 교환 전후 의미가 같은 항목과 다른 항목을 표로 제공한다.

**재사용 위치:** `event_log`, `ocel`, `tabular`, `model_io`, `tests/ocel`, `tests/model_io`, `tests/tabular`, `tests/test_log_imports.py`. 신규 XES writer·CLI 테스트는 기존 테스트 위치와 겹치지 않게 구현 단계에서 확정한다.

## 5. R02 — Case 선택·시간·집계

**업무 결과:** 어느 실행을 골랐는지와 대기·처리·반복 경로의 시간이 왜 그 값인지 설명한다.

입력은 원본 ID와 순서를 가진 CaseLog, 선택 조건, 시간 정책이다. 필터는 event를 고르는지 case 전체를 유지하는지 구분한다. prefix/suffix/부분열은 원본 occurrence를 유지한다. 빈도 동률과 coverage 경계, 시간창의 시작·종료·포함·교차는 각각 별도 조건으로 제공한다. 달력시간과 업무시간을 섞지 않는다. 동시 수행 구간의 합과 합집합 길이를 구분하고, service/sojourn/waiting은 lifecycle과 overlap 처리 정의를 함께 제공한다.

반복 방문의 PRE/POST 시간, DFG performance, spectrum, cube, 분포 결과는 표본 수·결측 수·집계 단위와 근거 occurrence를 제공한다. 관측 로그의 확률 언어는 관측 빈도이며 모델 전체 행동 확률로 확대 해석하지 않는다.

**검증·인수:** 겹치는 interval, 자정·DST·휴일, 동일 활동 반복, 동시각, 진행 중 case, 0개 표본, 빈도 동률 사례의 손계산 표와 일치해야 한다. 화면용 합계와 원본 집계가 일치하고 누락·제외 이유를 추적할 수 있어야 한다.

**재사용 위치:** `case_centric/statistics.py`, `filtering.py`, `lifecycle.py`, 관련 case 테스트. 사용자에게 같은 작은 로그를 서로 다른 시간 정책으로 계산한 비교표를 제공한다.

## 6. R03 — Object 분석 단위·관계·변환

**업무 결과:** 한 객체·실행의 행동을 보면서도 공유 이벤트와 다른 객체의 관계를 잃지 않는다.

입력은 canonical OCEL과 객체형/실행 추출/시간창/closure 정책이다. flattening은 객체를 case로 삼는 투영으로 정의하고 같은 이벤트가 여러 case에 나타날 수 있음을 표시한다. 속성의 값은 정적 값과 시각별 값을 구분하며 as-of 경계와 동시각 충돌 정책을 기록한다. 여러 OCEL merge는 ID namespace, schema/type 충돌, 동일 이벤트 판정 규칙을 명시한다. Succinct/exploded 표의 행 수를 고유 이벤트 수로 계산하지 않는다.

variant는 먼저 동치 기준을 정한다. approximate signature는 후보 축소용이며 exact 동형 판정과 별도 결과다. 객체형·관계·순서 중 어떤 정보를 보존했는지를 결과에 남긴다. 실행 시간창은 시작/종료/포함/교차를 선택하고, event 선택 후 객체 보존 범위를 명시한다.

**검증·인수:** 두 주문이 하나의 배송 이벤트를 공유하는 사례, 속성 변경, ID 충돌 merge, 동시각, 고립 객체, approximate 충돌 후보를 사용한다. 투영 전후 event/object ID와 증식·손실 목록을 확인한다. exact 비교는 작은 graph의 전수 대응으로 독립 대조한다.

**재사용 위치:** `object_centric/transformations.py`, `equivalent_ocel.py`, `features.py`, `filtering.py`, `relations.py` 및 대응 테스트. 입력→객체별 활동열→공유 이벤트 연결을 사용자 샘플로 제시한다.

## 7. R04 — Case 모델 표현·변환·축약

**업무 결과:** 모델을 다른 표현으로 옮겨 계산해도 어떤 행동이 유지되는지 알 수 있다.

지원 표를 모델 종류×요소×계산으로 나눈다. BPMN의 추가 gateway/event, guard/update, 가중 arc는 각각 실행 의미를 먼저 고정한다. DI 표시 정보와 실행 요소를 분리한다. net→tree/POWL 변환은 가능한 구조를 판별하고 실패 시 원인 구조를 반환한다. 표현 불가능한 모델을 강제 tree로 변환하는 잔여 확장은 제외한다.

축약과 분해에는 원본 노드/arc와 결과의 대응을 유지한다. marking equation은 하한이지 실행 가능성의 충분조건이 아님을 구분한다. soundness는 종료 가능성·완료 marking·dead transition 등 선언한 정의를 검사하며 탐색 중단은 미판정으로 남긴다. 기존 reset/inhibitor·최대 분해를 다시 처음부터 구현하지 않는다.

**검증·인수:** 규칙마다 적용 전제와 보존 논리를 기록하고 작은 유한 모델의 행동을 독립 열거한다. 가중 arc·silent loop·deadlock·비정형 gateway·unbounded 예제를 포함한다. 작은 예제의 행동 일치만으로 모든 모델의 보존을 증명했다고 하지 않는다. solver 실제 실행과 선택 의존성 부재 진단을 별도로 검증한다.

**재사용 위치:** `case_centric/model_conversion.py`, `extended_nets.py`, `maximal_decomposition.py`, `marking_equation.py`, `model_analysis.py`, `model_io` 및 대응 테스트. 변환 전후 모델·허용 trace·거부 사유를 나란히 제시한다.

## 8. R05 — Case 발견

**업무 결과:** 동일한 로그에서 어떤 가정·threshold 때문에 다른 모델이 발견되는지 설명한다.

Heuristics의 AND/loop, interval 기반 동시성, Split Miner의 OR-join, POWL 부분순서와 footprint를 profile로 구분한다. 동명 활동과 반복 occurrence를 구별하고 입력에서 잃어버린 상관관계를 복원했다고 주장하지 않는다. Case ID 없는 흐름 추정은 관측 연결과 추정 연결을 구분한다. Local Process Model은 후보 생성·품질·탐색 한도를 반환한다.

**ILP 예외:** 기존 지원 상태를 보존한다. 예제·region/제약 정의·solver 대안·탐색 한계 학습 자료까지만 준비하고 공동 설계 전 구현을 시작하지 않는다.

**검증·인수:** 순서·XOR·AND·loop·noise·중첩 lifecycle을 구별하는 작은 로그에서 모델과 관측/추정 관계를 대조한다. threshold 경계, event 이름 변경, 빈 로그를 검증한다. 참조 차이는 profile 차이인지 오류인지 설명한다.

**재사용 위치:** `case_centric/heuristics.py`, `split_miner.py`, `powl.py`, `extended_discovery.py` 및 대응 테스트. 같은 로그의 threshold 변화 샘플을 제공한다.

## 9. R06 — Case 적합성·alignment

**업무 결과:** 어떤 동작이 모델과 다르며 그 판단이 확정인지 탐색 중단인지 구별한다.

공통 계약은 log/model/synchronous move 비용, 초기·최종 상태, silent 전이, 동률 해, 종료 한도다. backward replay의 보정 정책과 token 지표를 명시한다. 분해 alignment는 공유 전이의 일관성을 검증한 뒤 합치고 국소 최적해의 단순 합을 전역 최적이라고 선언하지 않는다. 근사는 유효한 상하한·오차 근거가 있는 경우에만 보장으로 표시한다. 대표 variant 집계는 빈도 가중과 미관측 행동 범위를 구분한다.

Multi-alignment는 합거리와 최대거리 목적을 선택하도록 제안한다. 최소 예제에서 두 목적이 다른 대표 실행을 선택하는 결과를 보여준 뒤 목적을 검토한다. 비용·길이 제한이 결과에 미친 영향을 기록한다. 대표 실행을 Agent의 자동 실행 지시로 연결하지 않는다.

**검증·인수:** 작은 유한 net/trace의 독립 전수해와 최소비용 결과를 비교한다. 0비용·silent cycle·동률·불가능·시간 제한·부분 탐색·공유 전이를 포함한다. 단일 trace API가 부적합과 미판정을 혼동하지 않아야 한다.

**재사용 위치:** `case_centric/alignment_search.py`, `decomposed_alignment.py`, `backwards_replay.py`, `advanced_precision.py`, 대응 테스트. move별 비용과 원본 event를 연결한 샘플을 제공한다.

## 10. R07 — OC 발견·모델·적합성·성능

**업무 결과:** 객체가 함께 참여하는 행동에서 발화 조건·오류·대기를 계산한다.

OCPN의 객체 token, variable arc, 가중치와 cardinality를 분리해 정의한다. PM/OCPA 계열 발견은 공통 계산을 재사용하되 필터·variable arc 판정 차이를 profile로 유지한다. causal net 변환은 객체 흐름 제약을 보존하는 범위만 지원한다. Replay의 backward search·cache·flooding은 결과 의미와 탐색 전략을 구분한다. Context fitness/precision과 OPERA 계열 지표는 객체형·활동·arc별 모집단과 분모를 표시한다.

성능 중앙값·표준편차는 원시 duration 표본과 집계 단위를 확인한 뒤 추가한다. 캐시는 입력·모델·정책·판본이 같을 때만 재사용하며 정정 후 오래된 결과가 남지 않게 한다.

**검증·인수:** 객체 1:N 참여, 동일 객체의 재방문, 공유 이벤트, 가변 참여수, 결측 lifecycle, deadlock, 정정 후 cache 무효화를 검증한다. 작은 OCPN의 발화를 독립 열거하고 표본 시간은 손계산한다. 도메인 샘플은 객체별 token 이동과 병목 근거를 함께 제시한다.

**재사용 위치:** `object_centric/models.py`, `discovery.py`, `legacy_discovery.py`, `model_integration.py`, `conformance.py`, `performance.py` 및 대응 테스트.

## 11. R08 — Feature·학습·n-gram·검정

**업무 결과:** 실행을 비교·검색·예측할 수 있는 수치로 표현하고 그 정보가 언제 이용 가능했는지 설명한다.

입력은 선택한 활동열/관측 시점/학습 모집단과 feature 정의다. split은 case·객체 공유·그룹·시간 경계를 존중한다. 분기 직전 feature는 미래 결과를 포함하지 않는다. 모델 좌표별 feature는 모델 판본과 대응 좌표를 유지한다. 군집은 scaling·seed·표본 변동에 대한 안정성을 보고하고 drift는 무변화 오탐과 실제 변화 검출을 별도 실험한다. Transformer 실제 추론은 runtime·checkpoint·출력 shape·재현 조건까지 검증한다.

**n-gram 설계:** 활동 ID 또는 구조화한 활동·도구·상태 조합을 토큰으로 사용한다. case/객체/실행별 활동열의 경계를 넘지 않고 겹치는 연속 묶음을 센다. n 범위, 동시각 순서, 결측, 미등록 토큰과 어휘 한도를 명시한다. Count/binary/TF-IDF는 동일한 토큰 inventory를 공유한다. 최초 TF-IDF profile 제안은 raw count TF, `log((1+N)/(1+df))+1` IDF, 선택적 L2 정규화이며 공식과 옵션을 결과에 남긴다. 학습 모집단에서만 어휘·IDF를 맞춘다. 이 공식은 설계 제안이지 기존 참조와의 동등성 선언이 아니다.

PM-ADV-004/005는 각각 case 요약 feature 추가, 이벤트 sequence feature schema 추가다. 기존 encoder/tensor는 유지하고 미판정 확장만 선택 사항으로 남긴다. n-gram 구현을 위해 두 확장 전체가 필요하다고 가정하지 않는다. Word2Vec/Doc2Vec의 추가 옵션은 보류안이며, 외부 embedding은 모델·판본·전처리·차원을 표시해 비교한다.

**검증·인수:** `검색→열기→검색→열기→저장` 및 `A→A→A`의 1/2/3-gram 손계산, 빈/짧은 열, 객체 경계, 동일 활동 수지만 순서가 다른 두 열, token 충돌, 결측, 학습/검증 누출, 미등록 토큰을 검사한다. TF-IDF는 작은 문서 3개로 독립 계산한다. 통계 검정은 seed를 고정한 실험 설계와 표본 수를 기록하며 한 번 통과한 결과로 일반 검출력을 보장하지 않는다.

**재사용 위치:** `case_centric/features.py`, `feature_dataset.py`, `embeddings.py`, `decision_evaluation.py`, `drift_evaluation.py`, `object_centric/learning.py` 및 대응 테스트.

**사용자 샘플 필수:** 일반 업무/Agent 예제에서 원본 활동열과 1/2/3-gram 표, count/binary/TF-IDF 비교, 객체를 잘못 섞었을 때의 허위 패턴을 실제 PIX 출력으로 만든다. 실행 명령·입력·결과 파일·테스트 결과를 함께 제공한다. [기존 n-gram 추가 설계](2026-09-13_PIX_DETAILED_DEVELOPMENT_PLAN.md#ngram-design-2026-09-18)와 같은 요구다.

## 12. R09 — 자원·조직 지표

**업무 결과:** 누가 누구에게 일을 넘겼고 어떤 역할·부하가 관측되는지 계산한다.

인계는 이벤트 순서와 자원 변경을, 공동 작업은 case 참여와 쌍 가중치를, subcontracting은 반환 구간을 각각 정의한다. 완료 여부와 기여도는 같은 지표가 아니다. Multitasking은 interval 겹침을 기반으로 하고 순간 이벤트만 있을 때 지속 부하를 추정했다고 표시하지 않는다. 0벡터·단독 자원·결측 자원·동시각 정책을 포함한다.

**검증·인수:** 3개 자원·2개 case의 손계산 network와 denominator를 제공하고 반복 인계·동시 작업·부분 관측을 검증한다. 역할 발견의 입력 perturbation에 대한 안정성을 측정한다. Agent를 resource로 분석할 때도 이 지표를 곧바로 성과·책임으로 해석하지 않는다.

**재사용 위치:** `case_centric/organization.py`, `tests/case_centric/test_organization.py`. 지표별 분자·분모와 원본 구간 표를 사용자에게 제공한다.

## 13. R10 — 시뮬레이션·확률 언어

**업무 결과:** 모델과 관측 자료를 이용해 가능한 실행·시간·자원 사용을 비교한다.

관측 duration/전이 빈도 → 추정 분포 → 모델 발화·queue·resource 정책 → 실행 표본 → 비교 지표를 분리한다. 처리시간·대기시간의 중복 반영을 막고 검열된 미완료 실행을 완료 표본과 분리한다. seed, 분포 추정 모집단, 적합 방법과 종료 한도를 기록한다. 미관측 상황의 분포는 자동 보장하지 않는다.

PN/tree/DFG의 무작위 생성·유한 열거·확률 절단은 서로 다른 출력이다. 무한 언어의 절단에서는 남은 확률 질량의 유효한 bound가 없으면 정확 거리로 표시하지 않는다. 자원 충돌·동시 발화·tie-breaking은 명시 정책으로 제공한다. PM-SIM-010의 관측 Agent 분포 활용은 원래 합성 tree 호환 작업과 별도 범위 조정안으로 추적한다.

**검증·인수:** 작은 모델의 허용 실행 전수해, 확률 합, 종료 확률, 불완전 실행, 자원 1개/2개, queue 경합을 검사한다. 고정 seed 재현과 여러 seed 분포 검사를 구분한다. holdout 관측과 시뮬레이션의 duration/경로 분포를 비교하되 일치하지 않으면 가정을 수정한다.

**재사용 위치:** `case_centric/simulation.py`, `timed_playout.py`, `resource_simulation.py`, `object_centric/simulation.py` 및 대응 테스트. 같은 모델의 자원 수 변경 비교 샘플을 제공한다.

## 14. R11 — Stream 정정·재계산·복구

**업무 결과:** 늦게 도착하거나 수정된 이벤트를 반영해도 batch 계산과 선언한 동일 결과를 얻는다.

이벤트 ID와 revision, 출처 offset, 정정/삭제/중복, 열린 관측을 구분한다. 먼저 현재의 재계산 경로를 정답 기준으로 두고 DFG·replay·temporal·Declare·footprint별 증분 상태를 설계한다. OC 정정으로 execution이 합쳐지거나 나뉘면 영향 집단과 기존 결과의 무효화를 기록한다. Online alignment의 기억 제한과 look-ahead는 정확도/완료 범위에 포함한다.

PIX는 계산 상태 snapshot과 복원 검증을 제공하고 Schumpeter는 메시지 보관·재전달·offset의 durable 저장을 담당하는 구성을 제안한다. 두 저장소를 잇는 트랜잭션 근거 없이 exactly-once를 약속하지 않는다. 초기 목표는 재전달을 허용하면서 중복 계산 효과를 제어하고 결과를 재현하는 것이다.

**검증·인수:** 순서 바뀐 입력, 동일 revision 재전송, 삭제 후 재삽입, 실행 분할/합병, 처리/저장/확인 사이의 장애 지점에서 복원한다. 동일 최종 사실 집합의 batch 결과와 비교한다. 지연·기억량은 실제 규모에서 측정하고 상한 초과를 진단한다.

**재사용 위치:** case/object의 `revisable_stream.py`, `case_centric/online_alignment.py`, streaming·stream adapter 테스트. 정정 전후 수치와 복구 과정을 샘플로 제공한다.

## 15. R12 — 제약·action 영향·privacy

**업무 결과:** 어떤 제약이 관측 자료와 맞지 않고 개입 전후 무엇이 달라졌는지 근거를 제공한다.

Constraint 발견은 후보·support·반례·시간창을 반환한다. Action 구조 영향은 방향·객체형·도달 범위를, 성능 비교는 cohort·관측 기간·결측·교란 가능성을 표시한다. 단순 전후 비교를 인과 효과라고 하지 않는다. 최적 행동 추천으로 연결하려면 목적·제약·실행 가능성과 no-op 대안을 별도 정의한다.

Privacy는 공개 단위·인접 데이터 정의·epsilon 등 예산·합성/구성 방식·공개 출력 범위를 먼저 고정한다. 제어흐름 익명화와 timestamp/속성 재결합의 보장은 별도 검토한다. 공개 결과에 원본 식별자를 그대로 붙이는 근거 추적은 금지하고 내부 감사 근거와 공개 산출물을 분리한다.

**검증·인수:** 지지/반례가 모두 있는 작은 OCEL, cohort가 바뀐 전후 비교, 구조만 바뀐 action을 검사한다. Privacy는 수학적 보장 검토와 구현 검증을 함께 요구하며 공격 실험 통과만으로 보장하지 않는다. 보장을 입증하지 못한 결과는 공개 가능 상태로 승격하지 않는다.

**재사용 위치:** `object_centric/constraints.py`, `action_planning.py`, `operational_impact.py`, `case_centric/privacy.py`, `sacofa.py`, `pripel.py` 및 대응 테스트.

## 16. R13 — 시각화와 제품용 검토 샘플

**업무 결과:** 계산 값을 그래프·표에서 읽고 그 근거로 이동한다.

Graphviz 기본 배치와 무채색 스타일, OC variant chevron의 가로/세로 선택을 유지한다. DFG/OCDFG/OCPN/PN overlay는 각 계산의 집계 단위와 결측/미판정 표시를 전달한다. POWL 부분순서, BPMN 요소, interleaving link는 표현 가능한 의미를 명시한다. Top-N·필터·상대시간·log 축은 모집단 변경·0·결측 처리와 함께 표시한다.

**검증·인수:** 화면/내보내기 숫자를 원 계산과 대조한다. 긴 한글 label, 큰 수, 빈 graph, 병렬 edge, 가로/세로, zoom/export, 대형 graph 필터 후 근거 링크를 실제 렌더로 확인한다. 글자 잘림과 단위 혼동은 인수 실패다. 대표 샘플의 입력·옵션·SVG/HTML·검토 결과를 함께 보관한다.

**재사용 위치:** `viewer`, `tests/viewer`. 새 앱 전체 구축은 이 잔여 시각화 확장에 자동 포함하지 않는다.

## 17. R14 — Agent·Schumpeter 경계

**업무 결과:** Agent가 만든 사실을 계산하고 그 결과를 Hub가 다시 사용할 수 있다.

| 책임 | PIX | Agent/Schumpeter |
| --- | --- | --- |
| 외부 수집 | 수집된 문서의 파싱·mapping·검증 | 브라우저/OS/GitHub/HTTP 등 자료 취득, 인증·재시도 |
| 의미 연결 | 명시된 event/object/type/qualifier 검증, 원본 ID 보존 | 어떤 관측이 어떤 행동·객체인지 계측하고 mapping 제공 |
| 계산 | 표준화된 spec을 받아 모델·지표·근거 반환 | 작업 선택·목적·실행 순서·사용자 상호작용 |
| LLM | 명시 질의/벡터 입력과 계산 결과·근거 계약 | 모델 선택·호출·자연어 해석·가설 제안 |
| 전달·복구 | 계산 상태와 revision·snapshot 계약 | broker·backpressure·durable 저장·재전달 |

브라우저 전용 계약은 필수로 가정하지 않는다. 공통 profile로 표현 가능한지 먼저 본다. 예제 후보는 Agent·탭·문서·작업을 객체로, 탐색 요청·문서 로드·클릭을 이벤트로 연결하는 방식이다. 시각/ID만으로 사용 의도·성공·인과관계를 추정하지 않는다. 기존 OCEL 표현으로 충분하면 새 규격을 만들지 않는다. 불충분한 사례가 확인되면 추가 qualifier/속성 mapping을 별도 version으로 설계한다.

자연어 질의는 검토 가능한 필터·질의 계획으로 변환하고 PIX 계산과 결과를 연결한다. LLM regex 군집은 기본 계산 범위에서 제외한 기존 표를 유지하되, 패턴 가설을 명시 검사하는 경로로 흡수하는 안을 기록한다. 그림 설명은 Schumpeter 후보이며 구조화된 모델 근거가 있으면 함께 전달한다. 임의 Python 함수 실행과 특정 upstream 호출 모양의 복제는 일반 필터 기능과 구분한다.

**검증·인수:** Agent가 미리 만든 이벤트 fixture로 중복/잘못된 ID/미지원 타입/시각 누락/버전 차이를 검사한다. 수집기 설치 없이 PIX 입력 검증이 동작해야 한다. LLM 없이 저장된 질의 계획·벡터로 계산을 재현한다. 실제 Hub 운영 검증은 PIX 단위 테스트로 대신하지 않는다.

## 18. 구현·검증·도메인 검토 절차

각 ID는 추적표의 작업 묶음과 기존 평가에 연결한다. 구현 직전에 현재 코드와 테스트를 읽어 실제 잔여만 확정한다. 오래된 gap 문장을 미구현 사실로 그대로 사용하지 않는다.

1. **정의 카드:** 업무 질문, 입력/모집단, 공식·순서·분모, 지원 범위, 반례, 사용자 예제를 작성한다.
2. **차이 카드:** 기존 기능으로 가능한 것과 새로 필요한 것, 수정 모듈·테스트 파일을 기록한다. 이미 충족되면 추가 구현 없이 검증한다.
3. **작은 검증:** 손계산 또는 독립 전수해, 잘못된 입력, 경계/중단/결측을 테스트 파일에 넣는다. 구현식을 복사한 기대값은 피한다.
4. **실제 사용 검증:** XES/OCEL corpus 또는 해당 모델 fixture에서 공개 API를 실행하고 입력 hash·환경·옵션·명령·결과를 남긴다. 로그 corpus만으로 모델 변환이나 privacy를 검증했다고 하지 않는다.
5. **사용자 검토:** 입력→결과→해석→한계를 표/그림으로 제시한다. n-gram 샘플은 필수다. 동의하지 않은 의미는 새 기본값으로 확정하지 않는다.
6. **완료 기록:** 구현, 실행 검증, 참조 차이 검증, 도메인 검토를 별도 상태로 기록한다. skip/미실행을 통과로 집계하지 않는다.

테스트 파일은 기존 영역 테스트를 우선 확장한다. 필요 시 새 테스트 파일을 만들며 문서의 테스트 계획을 실행 증거로 표시하지 않는다. 변경 영향에 맞는 테스트를 먼저 실행하고 새로운 변경·실패·미해결 위험이 없으면 불필요한 반복을 하지 않는다.

## 19. 근거·유효기간·반증 조건

근거는 현재 공동 체크리스트, 대화의 명시 결정, [2026-09-18 평가](../reports/2026-09-18_PIX_PM4PY_OCPA_COMPLETION_ASSESSMENT.md), 기존 계획과 모델/W4 보고서다. 소스 구조·공통 결과 계약·feature/stream 진입점을 이번에 확인했다. 모든 알고리즘을 이번 설계 작업에서 다시 감사하거나 실행하지는 않았다.

- 결정과 제안은 구분한다. 필요 표는 기능 도입 의사이며 여기 제안한 모든 수식·default의 도메인 승인은 아니다.
- 유효기간은 2026-09-18 체크리스트/요구와 평가 기준 코드에 한정한다. 코드·사용처·입력 계약 변경 시 관련 설계를 재검토한다.
- 손검산 반례, 원본 손실, 모집단 혼합, 미래 정보 누출, 복구 불일치, 보장 없는 정확/최적 표시가 발견되면 해당 설계 또는 완료 판정을 철회한다.
- 기존 기능으로 충분하면 무추가개발을 선택한다. 미판정이나 착수 보류를 편의상 필요/불필요로 바꾸지 않는다.
- 개발 인시·기간·전체 성공률·처리 규모·성능 개선치는 현재 알 수 없음이다. 실측 후 기록한다.

이 문서와 추적표는 세부 개발의 출발점이며 코드 변경·계산 테스트 통과·출시 승인을 의미하지 않는다.
