# PIX native OCPN discovery v1

검토 기준: 2026-09-10. 구현 위치는 `src/pix/compute/ocpn_discovery.py`, 검증 파일은
`tests/compute/test_ocpn_discovery.py`이다. PM4Py/OCPA 실행 코드에 의존하지 않는다.

## 입력 범위와 구조

호출자가 객체 유형, `observed_range` 참여 수 정책, `unique_activity` 병합 정책을
명시한다. OCEL 이벤트 유형 이름이 활동의 의미적 식별자다. 화면의 표시 이름을
비교해서 노드를 합치는 방식이 아니다. 원본 OCEL의 모든 이벤트를 유지하며,
객체 집합만 명시적으로 선택한 유형에 한정한다. 선택하지 않은 객체 유형의
이벤트와 연결 없는 이벤트도 없어지지 않는다. 이 경우 선택된 객체 참여 수는 0이다.

각 객체 유형에서 객체별 이벤트 순서를 추출하고, 선택한 PIX 자체 발견기로
process tree를 만든 다음 수락 Petri net으로 변환한다. 기본 발견기는 기존
`pix.inductive_cut.v1`이며, 별도로 구현된 `pix.im.v1`을 명시적으로 선택할 수 있다.
무음 전이는 객체 유형마다 독립적으로 유지한다. 같은 활동의 가시 전이는 각
유형에서 해당 활동에 대응하는 전이가 하나일 때만 동기화한다. 한 유형 안에
동일 활동의 서로 다른 전이가 둘 이상 있으면 위치의 대응 관계를 추측하지 않고
`ambiguous_activity_merge`와 함께 계산 불가를 반환한다.

선택한 유형이 선언되지 않았거나 객체가 하나도 없으면 해당 유형을 건너뛰지 않고
계산 불가로 반환한다. 객체는 있지만 연결 이벤트가 없는 경우에는 빈 객체 trace를
포함한다. 이 객체의 초기 토큰과 최종 토큰, 수락에 필요한 무음 실행도 유지한다.
이는 알려진 유한 객체 집합에 관한 실행 모델이며 실제 객체 생성 시점을 추론하지 않는다.

## 참여 수는 관측과 제약을 분리한다

활동 × 객체 유형마다 원본 로그의 해당 활동 이벤트 **전체**를 분모로 삼아
참여 객체 수의 정확한 히스토그램을 저장한다. 한 객체가 여러 qualifier로 연결되어도
객체 수는 한 번만 센다. qualifier 필터를 선택하면 그 필터를 통과한 연결만 사용한다.

| 관측된 참여 수 | 아크 표현 | 의미 |
|---|---|---|
| 0만 관측 | 해당 유형과 아크 없음 | 이 활동은 해당 유형 객체를 binding에 포함하지 않음 |
| 1만 관측 | 고정 아크, 정확히 1개 | 관측 범위를 정확히 1로 제한한 프로파일 |
| 0과 1 | 가변 아크, 0–1개 | 특정 이벤트의 빈 객체 집합도 허용 |
| 1과 2 | 가변 아크, 1–2개 | 둘 중 하나를 선택해서 실행 |
| 1과 3 | 가변 아크, 1–3개 | 관측되지 않은 2도 허용하며 별도 진단 기록 |
| 2만 관측 | 가변 아크, 정확히 2개 | 고정 아크의 단위 1 의미를 변경하지 않음 |

모든 선택 유형에서 참여 수가 0인 활동은 아크 없는 가시 전이로 유지한다.
`zero_incidence_activities` 진단과 실제 이벤트 binding이 이를 드러낸다.
일부 선택 유형에만 0 참여가 있는 이벤트도 모든 관련 유형의 빈 집합 또는 실제
객체 집합을 명시한 binding으로 실행한다.

이 범위는 **관측 표본에서 추론한 주변 분포의 구간**이다. 업무상 반드시 따라야 할
규칙이라는 의미가 아니다. 예를 들어 `A(주문만)`과 `A(상품만)`을 관측하면 주문과
상품 양쪽 최소 참여 수가 0이 된다. 이 모델은 `A(둘 다 없음)`과 새로운 공동 참여
조합도 허용한다. `joint_cardinality_guarantee="marginals_only"`와
`observational_cardinality_bounds` 진단이 이 한계를 항상 표시한다.

## 수락 증거와 계산 불가

객체별 원래 활동 순서와 로컬 Petri net을 결합한 유한 탐색에서 정확한 수락 경로를
구한다. 무음 전이 외에 로그 이벤트를 삽입하거나 삭제하지 않는다. 탐색 상태 수는
`max_fitting_states_per_object`로 제한한다. 제한 때문에 수락을 확인하지 못하면
`fitting_search_limit`을 반환하며 수락 실패로 단정하지 않는다.

그 다음 원본 이벤트를 시간과 명시적 동률 정책에 따른 공통 순서로 처리한다.
각 참여 객체의 무음 선행 단계를 실행하고, 같은 이벤트에 연결된 실제 객체들을
하나의 가시 전이 binding으로 동기화한다. 마지막 무음 경로까지 실행한 뒤 모든
객체의 토큰이 선언된 최종 마킹과 정확히 같은지 확인한다. 계산된 결과에는 다음이 남는다.

- 발견한 OCPN과 선택된 실제 객체 집합, 초기·최종 마킹
- 활동 × 유형 참여 수 히스토그램과 추론된 아크 범위
- 유형별 trace 계산 ID, 발견 계산 ID, 로컬 모델 digest, 고립 객체 목록
- 로컬 전이에서 병합 전이로 이어지는 대응표
- 원본 이벤트 ID와 실제 binding의 대응표
- 처음부터 끝까지 실제로 실행한 무음·가시 binding 수락 경로

`computed`는 이 입력 로그와 이 객체 집합의 수락 경로를 검증했다는 뜻이다.
전체 모델의 soundness나 미래 로그의 fitness, precision을 보장하지 않는다.

## soundness 반례

다음 네 이벤트는 발견한 모델에서 수락된다.

1. `A(주문 o1, 상품 i1)`
2. `B(상품 i1)`
3. `A(주문 o1, 상품 i2)`
4. `B(상품 i2)`

주문 trace는 `A,A`이므로 `A` 반복을 허용하는 모델, 각 상품 trace는 `A,B`이므로
순차 모델이 된다. 관측 실행이 끝난 뒤 주문이 종료 대신 반복 무음 전이를 선택하면,
주문은 다음 `A`를 기다리지만 두 상품은 이미 종료되어 동기화할 수 없다. 로컬
모델들이 sound해도 병합 모델에는 도달 가능한 비최종 교착 상태가 생긴다.
시험 파일이 이 상태를 직접 생성하고 더 이상 활성화된 binding이 없음을 확인한다.

따라서 결과에는 `joint_soundness_not_established` 진단이 항상 포함된다.

## 검증 범위와 철회 조건

집중 시험에는 손으로 계산 가능한 수락 경로, 0·1·다중 참여, 구간의 빈 값,
qualifier 중복, 고립 객체, 연결 없는 활동, 모호한 동률, 중복 활동 전이 거부,
탐색 한계, 원래 입력 오류, 순열 불변 ID, 교착 반례와 발견기별 100개 고정 seed 로그를 포함한다.
각 성공 결과의 모든 binding을 공용 발화 의미론으로 다시 실행하고 최종 마킹을 비교한다.
외부에서 결과를 복원할 때도 계약 검증이 공급된 수락 경로를 유한 다중집합 연산으로
확인한다. 비활성화된 첫 단계, 잘못된 최종 마킹, 누락된 참여 수 프로파일, 모순되는
객체 수·고립 객체·전이 대응표는 성공 결과로 복원할 수 없다. 이는 경로를 새로
탐색하는 기능이 아니라, 제공된 증거가 자기 모순인지 확인하는 절차다.

이 판단의 유효 범위는 기록된 소스와 단위 incidence·유한 객체 binding 의미론이다.
활동 식별, 발견 알고리즘, 무음 전이 동기화, cardinality 의미론 또는 계약이 바뀌면
재검토한다. 정확한 수락 경로를 재실행할 수 없는 반례가 나오면 `computed` 수락 주장도
철회한다. 대규모 로그 처리량·메모리 한계와 기존 라이브러리 대비 성능 우위는
**알 수 없음**이다.
