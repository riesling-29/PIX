# 로컬 artifact 관리 가이드

PIX의 `.artifacts/`는 개발 중 생성한 그래프 시안, 실행 결과, 검증 보고서, 참고 자료, 임시 실행 환경을 보관하는 로컬 작업 공간입니다. 디렉토리 전체가 `.gitignore`에 포함되어 있으므로 일반 clone에는 그 내용이 없습니다. 이 문서는 저장소에서 공유하는 이름 규칙입니다.

로컬 자료가 있는 작업 환경에서는 `.artifacts/index.html`을 브라우저로 열어 시각화 썸네일과 컬렉션을 탐색합니다. `.artifacts/README.md`에는 간단한 읽는 방법이 있습니다. 목차는 실제 파일을 연결하는 정적 HTML이며, 외부 자원을 불러오지 않습니다.

## 디렉토리 이름

| 기준 | 이름 형식 | 예시 |
| --- | --- | --- |
| 작업 날짜가 확인됨 | `YYYY-MM-DD-category-topic/` | `2026-09-17-design-neutral-process-map/` |
| 특정 버전의 결과물 | `vX.Y.Z-category[-topic]/` | `v0.3.0-validation-package/`, `v0.5.0-validation/` |
| 날짜를 확인할 수 없음 | `undated-category-topic/` | `undated-validation-code-review/` |
| 여러 작업에서 쓰는 실행 환경 | `runtime-tool-version/` | `runtime-python-3.10/` |

영문 소문자와 하이픈을 사용합니다. 날짜는 기존 폴더명, 실행 기록 등 확인 가능한 근거를 따릅니다. 파일 복사·정리 시각만으로 원래 작업일을 추정하지 않습니다. 날짜가 확인되지 않으면 `undated`로 표시합니다. 버전 이름 역시 실제 버전과 연결된 자료에만 사용합니다.

분류는 다음 의미로 사용합니다.

| 분류 | 내용 |
| --- | --- |
| `design` | 디자인 검토 시안과 관련 근거 |
| `visualization` | 그래프 출력, 뷰어, 배치 비교, 시각화 구현 결과 |
| `demo` | 계산과 입출력 등 기능의 사용 예제 |
| `validation` | 테스트, 패키지·브라우저 검증, 계산 비교 결과 |
| `reference` | 외부 참고 자료, 요구사항·범위 조사 |
| `operations` | Commit·push 등 운영 기록 |
| `maintenance` | 파일 정리 등 작업 공간 유지관리 기록 |
| `review` | 개별 검토 스크립트 등의 보조 자료 |

새 결과물은 처음부터 정식 디렉토리에 생성합니다. 이름이 겹치면 기존 결과를 덮어쓰지 않고 주제를 구체화하거나 `-run-02`처럼 실행 순서를 붙입니다. 파일 단위로 보관할 때도 같은 접두 규칙과 원래 확장자를 사용합니다.

## 컬렉션 내부 구성

새 컬렉션에는 필요한 항목만 둡니다. 모든 작업에 빈 디렉토리까지 만들 필요는 없습니다.

```text
YYYY-MM-DD-category-topic/
  README.md       # 목적, 입력, 실행 방법, 해석 범위
  index.html      # 여러 화면이 있을 때의 진입점
  data/           # 계산 결과 또는 시각화 입력
  geometry/       # 배치 좌표와 재현 정보
  qa/             # 화면 캡처와 검증 결과
```

README에는 다음 정보를 남깁니다.

- 무엇을 확인하기 위한 결과인지, 어떤 데이터·버전을 사용했는지
- 재현 가능한 명령과 실행 환경
- 확인한 결과와 아직 확인하지 않은 범위
- 시안의 경우 제품에 적용되었는지 여부와 판단을 다시 검토할 조건

`data/`, `geometry/`, `qa/`는 향후 생성물의 권장 구성입니다. 과거 결과물의 내부 구조를 이 예시에 맞춰 소급 변경하지 않습니다.

## 2026-09-17 정리의 보존 정책

이번 정리는 최상위 컬렉션 이름을 통일하고 탐색 목차를 추가하는 작업입니다. 기존 컬렉션을 다른 깊이로 옮기거나 내부 파일의 이름·내용을 수정하지 않습니다. 검증용 원본, 이미지, JSON, HTML, 소스 스냅샷과 실행 환경은 함께 보존합니다.

이전 **디렉토리** 이름에는 새 디렉토리를 가리키는 숨김 junction을 둡니다. 과거 문서의 경로, 저장된 HTML의 상대 경로, 실행 스크립트의 기존 경로가 계속 연결되도록 하기 위한 호환 조치입니다. 새 문서와 명령에는 정식 이름을 사용합니다. 호환 링크를 실제 컬렉션과 별개의 결과물로 집계하거나 재귀 복제하지 않습니다.

최상위 개별 파일 다섯 개는 정식 이름으로 옮긴 뒤, 이전 이름에 바이트가 동일한 숨김 복사본을 남깁니다. 디렉토리 junction과 달리 이후 수정이 자동 동기화되는 관계는 아닙니다. 이 파일들은 과거 검증·참고 기록으로 보존하고, 새 작업은 정식 파일 또는 별도 실행 기록을 사용합니다.

정리 기록은 `.artifacts/2026-09-17-maintenance-artifact-organization/`에 보관합니다. `artifact-map.json`에 이전 이름과 정식 이름의 대응을 남깁니다. 실제 이동·내용 보존·경로 검증 결과는 그곳의 기록을 기준으로 확인하며, 이 가이드 자체는 검증 성공을 의미하지 않습니다.

과거 README와 보고서의 문구는 생성 당시의 증거입니다. 예를 들어 2026-09-17 무채색 프로세스 맵은 사용자에게 선호 방향을 확인받은 디자인 후보이지만, 그 사실만으로 제품 기본 렌더러에 적용되었다고 표시하지 않습니다. 현재 제품 동작은 [시각화 사용 가이드](VISUALIZATION_GUIDE.md)와 실제 구현을 기준으로 확인합니다.

## 저장소에 남기는 것

로컬 실행 부산물과 다운로드 원본은 `.artifacts/`에 보관합니다. 공동 작업에 필요한 설계 결정·검증 요약은 `docs/`, 정식 재현 예제는 `examples/`, 테스트 입력은 해당 fixture 정책에 따라 관리합니다. 로컬 목차를 공유하기 위해 `.artifacts/` 전체의 Git 제외를 해제하지 않습니다.
