# PIX v0.1.0 Package Foundation Baseline

- **문서 유형:** 버전 기준선
- **패키지 버전:** `0.1.0`
- **기준일:** 2026-07-26
- **상태:** Package foundation initialized / not production-ready

## 1. 버전의 의미

현재 PIX의 배포 메타데이터와 import namespace는 다음 버전을 선언한다.

```text
Distribution: pix
Import namespace: pix
Version: 0.1.0
```

이 버전은 설치 가능한 package foundation의 현재 식별자다. 정본 아키텍처에
정의된 모든 PIX v0.1 기능이 구현되었다거나 production readiness가 검증되었다는
뜻은 아니다.

## 2. 포함된 범위

v0.1.0 package foundation에는 다음이 포함된다.

- setuptools 기반 src-layout 패키징;
- Python `>=3.10` 선언;
- 런타임 의존성 없는 패키지 메타데이터;
- `contracts`, `compute`, `intelligence`, `projection` 계층 패키지;
- `engine.py`와 `api.py`의 책임 경계;
- 패키지 및 구조 모듈 import 검사;
- AST 기반 외부 프로젝트 및 계층 역방향 import 검사;
- pytest 및 Ruff 개발 설정.


하위 모듈은 현재 소유권과 import 경계만 선언한다. 알고리즘, 계약 클래스 또는
가짜 성공 결과를 포함하지 않는다.

## 4. 의존 경계

PIX가 보존해야 하는 외부 경계는 다음과 같다.

```text
Schumpeter → PIX
PIX ─X→ Schumpeter
```

내부 책임 흐름은 다음과 같다.

```text
contracts
→ compute
→ intelligence
→ projection
→ engine / api
```

PIX source는 Schumpeter, PIG, OCPX, PM4Py 또는 OCPA를 import하지 않는다.
PM4Py와 OCPA는 참조 대상이며 PIX의 런타임 의존성이 아니다.

## 5. 검증 기준선

2026-07-26에 다음 검사가 통과했다.

```text
python -m pip install -e ".[dev]"                         PASS
PYTHONDONTWRITEBYTECODE=1 python -m pytest -q -p no:cacheprovider
                                                            8 passed
python -m ruff check .                                     PASS
python -m ruff format --check .                            PASS
PIX package and layer-owner imports                        PASS
```

이 검사는 패키징과 선언된 import 경계의 내부 일관성만 입증한다. 프로세스
인텔리전스 계산의 정확성이나 production readiness를 입증하지 않는다.

## 6. 구현되지 않은 범위

다음은 v0.1.0 package foundation에 구현되어 있지 않다.

- ProcessDataset 및 구체적인 process contract;
- object projection 및 trace reconstruction;
- relation integrity, temporal, lifecycle, lineage, recovery 연산자;
- process finding, diagnostics 및 recommendations;
- process-state projection 동작;
- engine orchestration 및 public analysis API;
- PM4Py 또는 OCPA wrapper;
- Schumpeter adapter;
- 파일 importer, CLI, database 및 visualization.

검증되지 않은 기능의 실제 동작과 정확도는 알 수 없음이다.

## 7. 확인된 사실과 해석

### 확인된 사실

- `pyproject.toml`은 `version = "0.1.0"`을 선언한다.
- `pix.__version__`은 `"0.1.0"`이다.
- package foundation 검사는 위 기준선에서 통과했다.
- source에는 process algorithm 클래스나 함수가 없다.

### 해석

`0.1.0`은 최초의 설치 가능한 구조 기준선으로 사용할 수 있다. 이 해석은 기능
완료 선언이 아니라 이후 검증된 계약과 알고리즘 변경을 추적하기 위한 버전
출발점이다.

### 미확정 사항

- Python 3.10에서의 실제 설치 및 검사 결과;
- 첫 ProcessDataset 계약의 최종 형태;
- 첫 vertical slice와 operator의 선택;
- 알고리즘의 정확성, 결정성 및 성능.

## 8. 버전 문서 명명 규칙

버전 문서는 다음 위치와 형식을 사용한다.

```text
docs/version/v<MAJOR>.<MINOR>.<PATCH>_<UPPER_SNAKE_CASE_TITLE>.md
```

예:

```text
docs/version/v0.1.0_PACKAGE_FOUNDATION_BASELINE.md
```

같은 패키지 버전에 문서가 둘 이상 필요하면 의미가 겹치지 않는 제목을 사용한다.
문서 존재만으로 해당 기능의 구현 또는 검증 완료를 주장하지 않는다.

## 9. 철회 및 갱신 조건

다음 조건이 발생하면 이 기준선을 갱신하거나 버전 의미를 재평가해야 한다.

- `pyproject.toml`과 `pix.__version__`이 불일치하는 경우;
- concrete contract 또는 process algorithm이 추가되는 경우;
- 공개 API 동작이 최초로 제공되는 경우;
- 런타임 의존성이 추가되는 경우;
- import 경계가 변경되는 경우;
- 위 검증 명령 중 하나가 실패하는 경우;
- 새로운 정본 또는 ADR이 현재 패키지 구조를 대체하는 경우.

이 문서는 2026-07-26의 현재 working tree와 `pix 0.1.0` package foundation에
한해 유효하다.
