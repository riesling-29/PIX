# PIX v0.1.1 — OCEL Validation and Deterministic Builder Baseline

- **문서 유형:** 통합 버전 기준선
- **패키지 버전:** `0.1.1`
- **기준일:** 2026-08-08 (Asia/Seoul)
- **통합 구현 Git 기준선:** `1c6d753da00e4fdc077904ecb961a5558df0021c`
- **통합 기준:** 이 문서를 포함하는 commit
- **상태:** OCEL canonical construction and semantic validation baseline / not production-ready

## 1. 버전의 의미

PIX v0.1.1은 설치 가능한 Python package foundation과 불변 OCEL data model, validation report contract, dataset-wide semantic validator 및 deterministic builder를 하나의 공개 경계로 제공한다.

이 버전은 다음을 의미하지 않는다.

- 외부 OCEL 파일 형식 입출력이 구현되었다는 선언
- Process Intelligence 분석 연산자가 구현되었다는 선언
- Schumpeter 통합이 완료되었다는 선언
- 성능·보안·운영 안정성이 검증되었다는 선언
- production readiness 선언

기존 `v0.1.0_PACKAGE_FOUNDATION_BASELINE.md`는 package foundation이 최초 형성된 시점의 역사적 기준선으로 유지한다. 이 문서는 이후 구현된 OCEL owner들을 포함하는 통합 상태 기준선이다.

## 2. 패키지 기준선

```text
Distribution: pix

Python: >=3.10
Runtime dependencies: none

```

PIX source는 PM4Py, OCPA, pandas 및 Schumpeter에 의존하지 않는다. 참조 분석 문서는 존재하지만 해당 프로젝트를 runtime dependency로 사용하지 않는다.

## 3. OCEL owner 구조

```text
src/pix/ocel/
├── model.py
│   └── immutable OCEL data model and local invariants
├── report.py
│   └── immutable semantic validation result contract
├── validate.py
│   └── read-only dataset-wide semantic checker
└── build.py
    └── deterministic canonical construction and validation orchestration
```

실행 흐름은 다음과 같다.

```text
typed model components
        │
        ▼
      build()
        ├── materialize once
        ├── normalize aware datetime to UTC
        ├── canonical nested ordering
        └── canonical root ordering
        │
        ▼
   OCEL candidate
        │
        ▼
     validate()
        │
        ▼
      Report
        │
        ▼
BuildResult(candidate, report)
```

## 5. Immutable OCEL data model

`model.py`는 다음 canonical type을 표현한다.

| 영역 | Public type |
|---|---|
| 값 타입 | `ValueType`, `Value` |
| attribute 선언 | `Attribute` |
| type 선언 | `EventType`, `ObjectType` |
| attribute 값 | `EventAttr`, `ObjectAttr` |
| entity | `Event`, `Object` |
| relation | `E2O`, `O2O` |
| dataset root | `OCEL` |

model owner의 책임은 개별 값과 record를 표현하고 생성 시점의 로컬 불변식을 지키는 것이다. dataset 전체의 참조 무결성, duplicate 및 schema 의미 검사는 수행하지 않는다.

확인된 로컬 불변식에는 다음이 포함된다.

- frozen dataclass 기반 불변성
- tuple 기반 collection
- timezone-aware datetime 요구
- null·container·비유한 float 거부
- blank ID와 blank type name 거부
- event attribute name 중복 거부
- 동일 object attribute name·time 충돌 거부

## 6. Validation report contract

`report.py`는 dataset-wide semantic validation 결과를 불변 data contract로 표현한다.

```text
Issue
├── code: str
├── message: str
├── level: Level
└── at: tuple[str, ...]

Report
├── issues: tuple[Issue, ...]
├── valid
├── errors
├── warnings
└── has(code)
```

`Issue.at`은 source-file 위치가 아니라 OCEL semantic location이다. 빈 qualifier를 표현하기 위해 location 내부의 빈 문자열을 허용한다.

`Report.valid`는 `ERROR`가 없을 때 `True`다. `WARNING`만 있는 report는 valid다. Report는 validation을 실행하거나 입력 OCEL을 수정하지 않는다.

## 7. Dataset-wide semantic validation

`validate.py`는 다음 16개 규칙만 검사한다.

1. duplicate event type
2. duplicate object type
3. duplicate event ID
4. duplicate object ID
5. undeclared event type
6. undeclared object type
7. undeclared event attribute
8. undeclared object attribute
9. event attribute value type mismatch
10. object attribute value type mismatch
11. dangling E2O event
12. dangling E2O object
13. dangling O2O source
14. dangling O2O target
15. exact duplicate E2O
16. exact duplicate O2O

검사 의미는 다음과 같다.

- attribute declaration은 mandatory attribute를 뜻하지 않는다.
- disconnected Event와 Object는 valid다.
- Event ID와 Object ID는 별도 namespace다.
- qualifier는 relation identity의 일부다.
- 같은 endpoint와 다른 qualifier를 가진 relation은 duplicate가 아니다.
- INTEGER는 FLOAT declaration을 만족하지 않는다.
- BOOLEAN은 Python의 int subclass지만 INTEGER로 취급하지 않는다.
- duplicate type declaration은 grouping 후 보고하며 어느 schema도 임의 선택하지 않는다.
- 결과 issue는 deterministic order로 반환한다.
- 입력은 수정·정렬·병합·삭제·coercion·repair하지 않는다.

## 8. Deterministic builder

`build()`는 이미 PIX model class로 생성된 component iterable만 받는다.

```python
build(
    *,
    event_types=(),
    object_types=(),
    events=(),
    objects=(),
    e2o=(),
    o2o=(),
) -> BuildResult
```

builder는 다음 동작만 수행한다.

1. 각 iterable을 한 번 materialize한다.
2. timezone-aware datetime을 동일 instant의 UTC representation으로 바꾼다.
3. nested collection을 deterministic하게 정렬한다.
4. root collection을 deterministic하게 정렬한다.
5. immutable OCEL candidate를 생성한다.
6. `validate(candidate)`를 실행한다.
7. `BuildResult(candidate, report)`를 반환한다.

UTC normalization 대상은 다음과 같다.

- `Event.time`
- datetime-valued `EventAttr.value`
- `ObjectAttr.time`
- datetime-valued `ObjectAttr.value`

model이 naive datetime을 허용하지 않으므로 builder도 timezone을 임의 삽입하지 않는다.

canonical ordering key는 다음과 같다.

| Collection | Ordering key |
|---|---|
| `EventType.attributes` | name + `ValueType` |
| `ObjectType.attributes` | name + `ValueType` |
| `EventType`, `ObjectType` | name + schema signature |
| `Event.attributes` | name + deterministic value key |
| `Object.attributes` | name + UTC time + deterministic value key |
| `Event` | id + type + UTC time + attribute signature |
| `Object` | id + type + attribute-history signature |
| `E2O` | event + object + qualifier |
| `O2O` | source + target + qualifier |

builder는 record, entity 또는 relation을 삭제하지 않는다. duplicate도 병합하지 않는다. 따라서 invalid candidate 역시 원형을 보존한 채 validation report와 함께 관찰할 수 있다.

## 9. BuildResult contract

```text
BuildResult
├── candidate: OCEL
├── report: Report
├── valid: bool
└── ocel: OCEL | None
```

- `candidate`는 validation 성공 여부와 관계없이 deterministic하게 구성된 OCEL이다.
- `report`는 `validate(candidate)`의 결과다.
- `valid`는 `report.valid`에서 파생된다.
- `ocel`은 valid이면 candidate이고 invalid이면 `None`이다.

`BuildResult`는 frozen dataclass이며 candidate나 report의 상태를 수정하지 않는다.

## 10. 손실 방지와 비책임

builder와 validator는 다음을 수행하지 않는다.

- raw JSON dict, CSV row, SQLite row 또는 XES XML parsing
- input mutation
- duplicate merge 또는 삭제
- dangling relation 삭제
- disconnected entity 삭제
- identifier·qualifier coercion
- string trim 또는 case folding
- type·attribute inference
- int-to-float widening
- boolean/integer 변환
- naive datetime 보정
- timestamp·ID·UUID 생성
- sorting을 process trace 순서로 해석
- repair 또는 recovery

## 11. 검증 증거

2026-08-08에 cache provider를 비활성화하고 다음 결과를 확인했다.

```text
model tests:       12 passed
report tests:       9 passed
validate tests:    30 passed
build tests:       13 passed
owner regression: 64 passed
full suite:        72 passed
Ruff check:        PASS
Ruff format check: PASS — 9 files already formatted
public import:      PASS
```

추가 manual probe에서 다음을 확인했다.

- 입력 collection 순서 역전 후 candidate equality
- KST datetime의 동일 instant UTC normalization
- duplicate Event ID 보존과 validation error
- duplicate E2O 보존과 validation error
- 동일 endpoint·다른 qualifier relation 보존
- dangling relation 보존과 validation error
- disconnected Event/Object 보존과 valid result
- FLOAT declaration의 integer value 비확장과 mismatch
- 공백을 포함한 nonblank identifier/type의 비변경

이 증거는 현재 구현 범위의 동작을 지지하지만, 아직 존재하지 않는 입출력·분석·운영 기능을 증명하지 않는다.

## 12. 구현되지 않은 기능

다음 기능은 v0.1.1에 구현되어 있지 않다.

- CSV reader/writer
- SQLite reader/writer
- Parquet reader/writer
- XES reader/writer와 case-to-object mapping
- OCEL 2.0 JSON/XML/SQLite serializer와 deserializer
- 표준 형식 round-trip
- import policy, rejected record 및 source diagnostics
- process projection
- integrity·temporal·lifecycle·lineage·recovery operator
- findings·diagnostics·recommendations
- public analysis engine/API
- Schumpeter adapter와 integration test

`contracts`, `compute`, `intelligence`, `projection`, `engine.py`, `api.py`는 현재 owner boundary 또는 placeholder이며 구현 완료를 의미하지 않는다.

## 13. 알 수 없는 사항

현재 증거로는 다음을 산정할 수 없다.

- 지원 가능한 dataset 최대 크기
- 처리량과 메모리 사용량
- 외부 OCEL 2.0 producer/consumer 호환성
- 파일 형식 간 lossless round-trip 가능 여부
- 분석 결과의 정확도와 재현성
- production 보안·복구·운영 안정성

검증 대상 구현과 fixture가 없으므로 관련 수치는 모두 **알 수 없음**이다.

## 14. 유효기간과 철회 조건

이 기준선은 다음 조건 중 하나가 발생하면 재검증해야 한다.

- package version이 변경된다.
- `model.py`, `report.py`, `validate.py` 또는 `build.py`의 public contract가 변경된다.
- canonical ordering key 또는 UTC normalization 규칙이 변경된다.
- validation rule이 추가·삭제·변경된다.
- reader/writer, serializer 또는 format adapter가 추가된다.
- 현재 72개 테스트나 Ruff 결과가 달라진다.
- dependency boundary가 변경된다.

## 15. 결론

PIX v0.1.1은 설치 가능한 package foundation 위에 불변 OCEL data model, validation report contract, dataset-wide semantic validation과 deterministic canonical builder를 제공한다. 이 버전의 증명 범위는 typed in-memory OCEL construction and validation까지이며, 외부 파일 입출력, Process Intelligence 연산자, Schumpeter 통합 및 production readiness는 포함하지 않는다.
