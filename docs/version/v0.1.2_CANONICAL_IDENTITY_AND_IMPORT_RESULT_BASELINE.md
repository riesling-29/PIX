# PIX v0.1.2 Canonical Identity and Import Result Baseline

- **Document type:** version baseline
- **Package version:** `0.1.2`
- **Baseline date:** 2026-08-22 (Asia/Seoul)
- **Status:** canonical identity and import-result contracts implemented; not production-ready
- **Integration baseline:** the commit containing this document

## 1. Scope

PIX v0.1.2 extends the validated in-memory OCEL core with two Phase 1 contracts:

1. a versioned deterministic serializer and SHA-256 identity for valid PIX OCEL
   datasets;
2. an immutable import result that keeps status, stage, issues,
   transformations, source evidence, and any constructed candidate separate.

This release does not claim that PIX can read or write an external event-log
format. PM4Py and OCPA are reference implementations only and remain outside
the runtime dependency graph.

## 4. Canonical V1 identity

The canonical identifier is `pix.ocel.canonical.v1`. Only a dataset accepted by
the current PIX semantic validator is eligible for canonical bytes and a
digest.

The serializer produces UTF-8 JSON without a BOM or final newline. It fixes
member ordering, collection ordering, datetime rendering, and tagged primitive
value rendering. SHA-256 is calculated over those exact bytes and exposed as:

```text
pix.ocel.canonical.v1:sha256:<lowercase-hexadecimal-digest>
```

The package version and canonical version are independent. A change to the
Canonical V1 byte representation requires a new canonical version rather than
a silent rewrite of V1. The normative rules and reconsideration conditions are
in `docs/specifications/PIX_OCEL_CANONICAL_V1.md`; golden vectors are in
`tests/ocel/golden/canonical_v1/`.

## 5. Import result contract

`ImportResult` distinguishes the following outcomes:

| Status | Meaning |
|---|---|
| `UNAVAILABLE` | source could not be obtained |
| `UNSUPPORTED` | source or format is outside the adapter's capability |
| `SYNTAX_INVALID` | source syntax could not be parsed |
| `SEMANTIC_INVALID` | a candidate was built but failed PIX validation |
| `VALID` | a valid OCEL and its canonical digest are available |

Issues are assigned to `SOURCE`, `SYNTAX`, `MAPPING`, `SEMANTIC`, or `PROFILE`
stages. Transformations and source evidence are recorded outside canonical
dataset identity. The contract enforces that only a valid result exposes an
`ocel` and canonical digest, while a semantic-invalid result may preserve its
candidate for diagnosis.

No concrete CSV, XES, OCEL JSON/XML, SQLite, or Parquet adapter is included in
this version.

## 7. Evidence limits

The current evidence does not establish:

- compatibility with OCEL 2.0 JSON, XML, or SQLite interchange formats;
- compatibility with PM4Py or OCPA import/export behavior;
- lossless round trips through any external format;
- maximum supported dataset size, throughput, or memory use;
- process-intelligence operator correctness;
- security, recovery, or production operational readiness.

Those values and guarantees are currently **unknown**.

## 8. Validity and withdrawal conditions

This baseline is valid until 2027-08-22, unless superseded earlier. It must be
withdrawn or revised if any of the following occurs:

- package metadata and `pix.__version__` disagree;
- Canonical V1 output differs from either committed golden vector;
- collection, primitive value, datetime, or identity semantics change;
- an invalid dataset receives canonical bytes or a digest;
- an `ImportResult` can represent contradictory status and evidence;
- a concrete external-format adapter or serializer is added;
- runtime dependencies or the PIX/Schumpeter boundary change;
- any test supporting the evidence above fails.

The evidence supports only the implemented in-memory identity and result
contracts at this commit. It does not support a claim that PIX already replaces
PM4Py or OCPA for file interoperability or process mining.
