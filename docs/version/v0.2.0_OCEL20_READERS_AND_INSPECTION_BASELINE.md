# PIX v0.2.0 — OCEL 2.0 Readers and Inspection Baseline

Date: 2026-08-22

## Scope

This baseline adds a dependency-free ingestion path for OCEL 2.0 JSON, XML,
and SQLite files. PM4Py and OCPA remain references only; neither is a PIX
runtime dependency.

## Public API

The task-oriented usage documentation is maintained in the
[OCEL reading user guide](../user-guide/OCEL_READING_GUIDE.md).

- `read_ocel(path, *, format=None) -> OCEL`
- `import_ocel(path, *, format=None) -> ImportResult`
- `OCEL.info()`, `OCEL.describe()`, and `OCEL.summary()`
- `OCEL.timezone_type`, `OCEL.timezone_info`, `OCEL.warnings`, and
  `OCEL.import_info`
- entity, type, E2O, and directed O2O lookup methods on `OCEL`
- `ImportResult.describe()`, `ImportResult.summary()`, and
  `ImportResult.require_ocel()`

The convenience reader raises `OCELImportError` when no valid OCEL is
available. The exception retains the complete `ImportResult` in `result`.

## Evidence and failure boundary

The importer records the source path, byte size, SHA-256 hash, detected format,
disclosed transformations, import issues, semantic validation report, and a
canonical digest for valid candidates. Failures are separated into source,
syntax, schema, mapping, and semantic stages. A semantically invalid mapped
candidate is preserved; pre-semantic failures do not fabricate one.

The adapters do not deduplicate, drop, or merge source records. Timestamps with
numeric offsets are represented in UTC without changing their instants.
Supported legacy timestamps with explicit offsets are parsed automatically.
When timezone information is absent, the reader assumes UTC, emits an aggregated
`TimezoneAssumptionWarning`, and retains structured provenance on the returned
OCEL. These representation details do not affect canonical identity.

## Verified behavior

The automated suite verifies equivalent JSON, XML, and SQLite documents produce
the same immutable OCEL and Canonical V1 digest. At this baseline, 112 automated
tests passed under Python 3.11.9.

The local Order Management sample was also read from all three formats with
21,008 events, 10,840 objects, 147,463 E2O records, and 28,391 O2O records. All
three representations produced the same digest:

`pix.ocel.canonical.v1:sha256:20128100b5200ac48ca0b24858588bf0bc93e98862f40eb8a74ac4cfb79aff29`

The local Hinge Production XML sample mapped and validated with 38,528 events
and 23,771 objects. These fixture observations apply only to the inspected
files and do not establish universal producer compatibility.

## Known boundary

The inspected Procure-to-Pay samples do not yet map to a valid PIX candidate.
All three representations contain duplicate object-attribute assignments at an
identical name and time. Their timestamp representations are now accepted by
the default timestamp policy, but PIX does not silently remove duplicate source
records.

This conclusion must be revised if the source fixtures change, the canonical
local invariants change, or an explicit producer-compatibility profile is
introduced. The baseline is valid for repository version `0.2.0` and the
fixtures inspected on 2026-08-22.
