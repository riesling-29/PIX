## 계산 정의와 적용 경계

Python 계산은 표준 라이브러리만 사용한다. PM4Py/OCPA/pandas/Graphviz를 실행하거나
설치할 필요가 없다. ELK는 좌표 배치에 사용하며, 모델 의미·집계·상호작용은 PIX에 있다.
로그 identity, 분석 요청 identity, 모델 identity, 그래프 좌표를 별개로 유지한다.

- 동시각의 객체 trace는 기본적으로 순서를 확정하지 않는다. `event_id` tie policy는
  명시적 선형화 가정이다. 인과관계를 입증하는 것으로 기록하지 않는다.
- Variant의 exact는 일관된 객체 이름 변경 아래 event/object incidence·유형·qualifier·
  객체별 순서·선택 범위·leading anchor에 대한 의미다. O2O, 속성, 절대 시각은 해당
  동치 정의에서 제외한다. 탐색 한도가 부족하면 그룹 일부를 exact로 발표하지 않는다.
- 시간 계산은 관측 event 간격과 명시한 시작 속성의 service time이다. 실행 모델의
  readiness가 필요한 waiting/sojourn 의미를 그 이름만 가져와 붙이지 않는다.
- `pix.inductive_cut.v1`은 보수적 자체 cut miner다. noise=0만 지원한다. 지원 cut으로
  분해되지 않는 경우의 flower fallback을 진단에 남긴다. 전체 IM/IMf/IMd 동등성을
  주장하지 않는다. 발견 모델은 관측되지 않은 추가 행동을 허용할 수 있다.
- Alignment는 명시적 비음수 정수 비용의 bounded Dijkstra다. 완료 trace의 최적 경로와
  한도 초과/도달 불가를 구분한다. Token replay는 별도의 국소 결정 정책이다.
  비용·token 수를 정규화 fitness로 명명하지 않는다.
- OCPN은 명시한 객체 universe와 초기/최종 marking에 대한 구체 binding을 실행한다.
  이것만으로 OCPN 자동 발견, 자동 binding 열거, 공동 alignment를 제공하지 않는다.
- 모델의 `provided`/`discovered`는 선언된 출처이며, 문서 digest는 내용 동일성 검사다.
  임의로 제공된 출처의 진실성이나 알고리즘 정답을 암호학적으로 인증하지 않는다.

계획표의 F 전체가 완료된 것은 아니다. Prefix/context precision, 업무 규칙 평가,
정규화 fitness, joint OCPN conformance는 아직 없다. OCPN discovery와 계획 G의
다른 miner·simulation·prediction 등도 후속 범위다. 이름뿐인 성공 API는 추가하지 않았다.

설치 검증한 배포물은 `.artifacts/package-verification/dist/pix-0.3.0-py3-none-any.whl`이다.
크기는 612,844 bytes이며 SHA256은
`a103d794f200332c52074e1e70c59549a1f21df9f57bd1355cd74e8a56e38def`다.
ELK 0.12.0, JS/CSS와 license를 포함하고 Python 필수 runtime dependency는 없다.
빌드·격리 설치 재현 방법은 `.artifacts/package-verification/README.md`에 있다.

정확성 검증에는 PIX 결과끼리의 비교 외에 독립 계산을 포함했다.
영속적인 `test_alignment_oracle.py`는 고정 seed의 유한 net 300개에서 별도
Bellman–Ford와 비교하고, 추가 탐색 한도 900건과 반환 경로의 발화를 검사한다.
이 oracle은 PIX firing 함수를 정답 계산에 사용하지 않는다.
Discovery 시험에는 작은 언어의 별도 token 실행과 유한 reachability 검사가 있다.
이 시험 결과를 모든 net의 soundness·최적성에 대한 일반 증명으로 확대하지 않는다.

독립 검토 과정에서 실제로 수정한 결함은 다음과 같다.

1. Python 3.10/3.11의 ISO timestamp 소수 파싱 차이를 입력 profile에서 정규화하고,
   microsecond를 넘는 nonzero 정밀도를 조용히 버리지 않도록 했다.
2. 하위 계산이 부모의 `invalid_input`과 구체 진단을 일반 unavailable로 소실하던
   경로를 수정했다. 부모 계산 참조와 부분 계산 상태도 보존한다.
3. 게시 성공 이후 임시 파일 정리 실패가 게시 실패로 보이거나 원래 오류를 덮던
   경로를 정리하고, 정리 진단을 별도로 남긴다.
4. Token replay에서 silent 목표 marking을 이미 찾고도 탐색 한도를 이유로 실패하던
   경우를 수정했다.
5. 자동 배치 완료 전 빈 SVG가 저장되지 않도록 막았다. 긴 모델의 전체 개요에서
   글자가 작아지는 경우 `Readable`로 선택 영역의 설계 글자 크기를 복원한다.

## 직접 확인하는 산출물

```powershell
python examples/native_pipeline.py --output .artifacts/native-demo
python -m pytest -q
node --test tests/viewer/test_layout.cjs
```

예제의 `process.html`은 OCDFG, `model.html`은 로그에서 발견한 classical Petri net,
`ocpn.html`은 별도로 제공한 공동 배송 OCPN이다. 세 HTML은 단독으로 offline에서 열린다.
OCEL JSON/XML/SQLite, 각 계산 JSON, 발견 모델과 제공 모델 JSON도 함께 만든다.
다시 같은 출력 경로에 실행하려면 `--overwrite`를 명시한다.

최종 생성한 세 HTML도 실제 Chromium에서 별도로 열어 확인했다. 한글 활동명,
관측 graph 4개 activity/5개 edge, 발견 Petri net 8개 node/8개 arc, 제공 OCPN
5개 node/4개 arc와 `[1,2]`/고정 1 참여 조건이 표시되었다. Browser error·외부 요청·
page overflow는 없었고, 화면 근거는 `.artifacts/native-demo/screenshots/`에 있다.
손으로 비교할 값은 `.artifacts/native-demo/README.md`에 기록했다.

실제 browser 검증은 별도 설치 후 명시적으로 실행한다.

```powershell
python -m pip install -e '.[dev,browser]'
python -m playwright install chromium
$env:PIX_RUN_BROWSER = '1'
python -m pytest tests/browser -q
Remove-Item Env:PIX_RUN_BROWSER
```

## 유효범위와 판단 철회 조건

근거는 2026-09-09의 이 구현, 지원 Python 버전에서 실행한 시험과 설치 산출물이다.
소스·Python·ELK 또는 알고리즘 정의가 바뀌면 관련 시험을 다시 실행해야 한다.
명시한 동치·집계·발화·최소 비용·보존 규칙을 깨는 독립 반례가 발견되면 해당 정확성
판단을 철회하고 오류 상태 또는 지원 범위를 수정한다.
대용량 처리량·메모리 상한·실제 환경의 오류 감소율·전체 외부 producer 호환성·
PM4Py/OCPA 대비 성능 우위와 대체 완성도는 **알 수 없음**이다.
