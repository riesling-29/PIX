# PIX 0.5.0 import 구현 및 검증 기록

기준일: 2026-09-12. 작업 트리의 0.5.0 구현과 아래에서 식별한 wheel에 대한 기록이다.
도메인 구조, 지원 프로파일, 사용 예제는 [입력 가이드](../design/2026-09-12-import-v050.md)에 정리했다.

## 구현 구조

`pix.import_log` / `pix.read_log`와 `pix.api`가 공통 진입점이다. OCEL 1·2·2.1 어댑터는 기존 canonical OCEL로 연결하고,
XES·MXML은 순서와 속성 계층을 보존하는 `CaseLog`로 읽는다. 업무 표는 명시적인 case 또는 객체 매핑으로 해석한다.
파일 감지는 XML BOM과 OCEL 버전 단서를 확인하며, 명시적 `format` 선택을 우선한다.

`case_traces`는 case의 기록 순서를 공통 `TraceSet`에 전달한다. 없는 시각은 `None`과 `unknown_timestamp`로 표시한다.
이 입력으로 PIX의 discovery, classical replay·alignment·precision을 사용할 수 있다. 시간·객체 중심 계산 및 기존 constraint
평가의 입력 요건은 별도로 유지한다. `to_ocel`은 사용자가 선택한 경우에만 case를 객체로 투영하고 원본 native 로그를 함께 보관한다.

결과 문서 `pix.analysis-result`는 **1.2.0**으로 확장했다. 새 `pix.case_traces` 결과와 nullable 시각을 저장하며,
기존 1.0.0·1.1.0 결과는 계속 읽는다. 기존 OCEL trace 결과에 시각 누락을 허용하지 않는다.
Canonical OCEL V1과 model 문서 1.0.0은 그대로 사용한다.

OCEL 2.1은 [공식 PDF](https://www.ocel-standard.org/2.1/ocel20_specification.pdf) **2.1.0pre4, 2026-08-24**에 고정했다.
SHA-256은 `b4fa1e9bcbc2c99b8c2f1aea4cb708fccb5e635070fd3474e07997f071e3b42e`다.
웹 요약과 다른 escape·첫 timed 속성 대입 규칙은 PDF를 따른다. 최종 표준 인증을 뜻하지 않는다.

## 단계별 검증

각 행은 서로 다른 신규 pytest test case 수다. 하위 검증 수나 wheel smoke 수를 더하지 않았다.

| 단계 | 통과 | 테스트 파일과 확인 내용 |
| --- | ---: | --- |
| OCEL 1 JSON/XML | 93 | `tests/ocel/test_legacy_import.py`: 원본 ID·고립 레코드, 타입 추론, metadata/default, gzip, 실패 진단 |
| Classic SQLite | 43 | `tests/ocel/test_legacy_sqlite_import.py`: 3-table dialect, 중복 사실 검증, NULL 정책, 읽기 전용·journal 경계 |
| Compact CSV | 67 | `tests/ocel/test_compact_import.py`: 4종 행, escaped reference, 타입 추론, 시각 보존, 충돌·정밀도 경계 |
| CSV/Parquet bundle | 77 | `tests/ocel/test_bundle_import.py`: 실제 typed Parquet, CSV, metadata, 이력, ZIP/디렉터리 안전성과 동일성 |
| Native case | 92 | `tests/event_log/`: XES/MXML 계층, globals/classifiers, 빈 trace, 순서, 명시적 OCEL 변환, native discovery/replay |
| 업무 표 | 128 | `tests/tabular/`: CSV/TSV/gzip/XLSX/rows, 명시적 매핑·format, 타입·ID·null·관계 충돌, 선택 의존성 |
| 공통 진입점·회귀 | 40 | `tests/test_log_imports.py`: UTF-16·gzip·형식 감지, native 모델 경계, 결과 구버전, 잘못된 시각, SQLite 연결 종료 |
| 합계 | **540** | bundle symbolic-link 생성 1개는 OS 권한 때문에 별도 skip |

통합 과정에서 재현한 오류는 회귀 사례로 남겼다. UTF-16 XES의 OCEL 오분류, OCEL 1 global 속성의 XES 오분류,
SQLite 감지 연결의 미종료, 소수 시·분 및 잘못된 offset의 정규화가 해당한다.
날짜만 있는 입력을 자정으로 만드는 경로도 거절한다. 기존 OCEL의 timezone 없는 시각에 대한 UTC 가정은 경고와 함께 유지한다.

## 전체 실행 결과

환경은 Windows / Python **3.11.15**, openpyxl **3.1.5**, pyarrow **25.0.1**이다.

| 검증 | 결과 | 기록 |

| Python 전체 회귀 | **4,184 passed, 284 subtests passed, 14 skipped**, 20.36초 | `.artifacts/v050/pytest.xml` |
| 실제 Chromium | **13 passed** | `.artifacts/v050/browser.xml` |
| JavaScript / ELK | **98 passed** | `.artifacts/v050/summary.json`의 명령 및 실행 결과 |
| Ruff lint | 통과 | `src`, `tests`, 두 wheel 검증 스크립트 |
| 변경 Python format | **42 files** 통과 | 기존 미변경 6개 파일의 formatter 차이는 별도 |
| 공백·lockfile | `git diff --check`, `uv lock --check` 통과 | 현재 작업 트리 |
| PIX-only 설치 | 새 import **20 checks**, 기존 native pipeline 통과 | `package/import-core-smoke/import-evidence.json`, `package/native-smoke/evidence.json` |
| 선택 의존성 설치 | 새 import **20 checks**, 실제 XLSX·Parquet 포함 | `package/import-extras-smoke/import-evidence.json` |

package 기록의 기준 디렉터리는 `.artifacts/v050/`다. 기본 suite의 skip 13개는 별도 Chromium 실행으로 확인했다.
나머지 1개는 symbolic-link 생성 권한 때문에 실행하지 못했고, Windows junction 거절 테스트는 통과했다.
20.36초는 이 환경에서 전체 테스트를 한 번 실행한 시간이며 로그 처리 성능 benchmark가 아니다.

```powershell
.venv/Scripts/python.exe -m pytest -q --junitxml=.artifacts/v050/pytest.xml
$env:PIX_RUN_BROWSER = '1'
.venv/Scripts/python.exe -m pytest tests/browser -q --junitxml=.artifacts/v050/browser.xml
Remove-Item Env:PIX_RUN_BROWSER
node --test tests/viewer/test_layout.cjs tests/viewer/test_model_layout.cjs tests/viewer/test_model_render.cjs
```

설치 검증은 wheel을 별도 venv에 설치한 뒤 저장소 밖에서 `python -I`로
`tools/check_native_wheel.py`와 `tools/check_import_wheel.py`를 실행했다.
core 환경의 설치 distribution은 `pix==0.5.0` 하나였다. extras 환경에는 openpyxl·et-xmlfile·pyarrow를 추가했다.
PM4Py·OCPA·pandas·Graphviz가 import되지 않는 경계도 확인했다.

## 유효 범위와 반증 조건

지원 범위는 문서화한 입력 프로파일이다. generic DB 네트워크 connector, 일반 업무 Parquet, `.xls`, XES/MXML writer,
OCEL 2.1 writer는 이번 import 범위에 포함하지 않았다. 표준 2.1 개정 또는 기존 프로파일 안에서 의미 보존 실패가
재현되면 해당 호환성 판단을 철회하고 어댑터와 회귀 검증을 수정해야 한다.

Python 3.10의 이번 코드 실제 실행, 모든 외부 생산자와의 호환율, 최대 처리량·메모리 규모, PM4Py/OCPA 전체 대체율은 **알 수 없음**이다.
이 기록은 위 날짜의 코드·명세 판본·wheel 및 유한한 검증 사례에 유효하다. 코드·입력 프로파일·의존성 변경 시 관련 검증을 다시 해야 한다.
