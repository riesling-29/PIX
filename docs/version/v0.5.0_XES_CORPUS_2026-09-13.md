# 사용자 제공 XES corpus 검증 기록 — 2026-09-13

## 입력과 디렉터리

사용자가 제공한 ZIP 2개와 gzip 1개에서 고유 XES 로그 9개를 확인했다. 일상생활 ZIP은 내부
`data.zip`에 로그 8개를 담고, 병원 청구 ZIP은 metadata·README·로그 1개를 담는다.
별도 병원 gzip은 ZIP의 payload와 동일하다. 사용자가 압축을 푼 뒤 아래 구조로 복사했다.

```text
tests/fixtures/event_logs/xes/
  manifest.json
  activities_daily_living/
    logs/    activitylog_uci_detailed_{labour,weekends}.xes.gz
             edited_hh{102,104,110}_{labour,weekends}.xes.gz
    source/  README.txt
  hospital_billing/
    logs/    Hospital Billing - Event Log.xes.gz
             Hospital Billing - Event Log.xes
    source/  DATA.xml, readme.txt
```

고유 로그 **9개**, plain/gzip 한 쌍을 포함한 실제 입력 파일 **10개**다. 원본 다운로드와 사용자
추출 폴더는 보존한다. 데이터, manifest, 실행 artifacts는 Git에서 제외한다.
기존 HingeProduction·OrderManagement·ProcureToPay 데이터는 이번 검증 대상이 아니다.

## 실행 환경

기존 `.venv/Scripts/python.exe`의 실행은 Windows Smart App Control이 차단했다.
보안 정책을 변경하지 않고 [공식 Python 3.13.15 배포본](https://www.python.org/downloads/release/python-31315/)을
별도 artifact 폴더에 준비했다. 다운로드 SHA-256은 공식 발표값과 일치했고, 포함된 실행 파일·DLL·PYD
30개의 Authenticode 서명이 모두 `Valid`였다. 이 배포본의 Python 실행, pytest 및 로컬 PIX import가 성공했다.

- 실행 파일: `.artifacts/xes-corpus-2026-09-13/runtime/python-3.13.15-embed-amd64/python.exe`
- Python **3.13.15**, pytest **9.1.1**, Windows x64.
- 공식 ZIP SHA-256: `d1f04d990aee1253d8569e8e5104e30fa9f5fa830899f14843448872d936a2cf`.
- 해당 runtime의 `python313._pth`에 현재 checkout의 `src`와 기존 `.venv/Lib/site-packages`를 명시했다.
  pytest의 순수 Python 의존성을 사용하며 site 자동 import와 pytest 외부 plugin 자동 로딩은 비활성 상태다.
- 기존 가상환경, 시스템 PATH, Windows 보안 정책은 변경하지 않았다.

재실행 명령은 PIX 프로젝트 루트 기준이다. 데이터나 환경이 없으면 테스트는 자동 다운로드하지 않는다.

## 원본 데이터에서 확인한 특성

일상생활 로그의 `Activity` classifier가 참조하는 열은 대부분 `Column_4`이지만,
UCI weekends는 `watchingtv`, HH104 labour는 `work`다. 8개 로그 모두 해당 열이 실제로 존재하며
원본 전체 대조에서 `concept:name`과 값이 같았다. `work`는 별도 전체 XML 검사로 확인했다.
테스트는 classifier 선언 자체와 선택한 열의 값을 검사하며 열 이름을 자동으로 변경하지 않는다.

일상생활 로그는 총 start 5,569건, complete 5,569건이다. 같은 건수라는 사실만으로 두 이벤트의
개별 짝이나 하나의 실행 구간을 확정하지 않는다. 병원 로그는 451,359건 모두 complete다.

원본 전체 검사에서 빈 trace, 직접 기록된 활동·시각의 누락, 해석 불가능하거나 시간대가 없는 시각,
event 직속 속성 key 중복은 관측되지 않았다. 같은 trace의 인접 이벤트 간 시각 역전은 0건이고,
동일 시각은 일상생활 합계 704쌍, 병원 505쌍이었다. PIX는 원본 순서를 유지한다.

이 데이터만으로 결측 시각·역전·classifier 값 충돌 등 모든 경계 사례를 입증할 수는 없다.
별도 인공 fixture를 포함한 기존 92개 회귀 테스트도 함께 실행했다.

## 분석 표본과 replay 한계

기본 활동 열은 `concept:name`이다. 선언된 classifier별 projection도 모두 `computed`였으며,
표본의 trace/event 개수·ID·순서·분류값·시각·관계를 원본 대조를 마친 CaseLog와 비교했다.
Discovery는 `pix.im.v1`, 깊이 상한 64를 사용했고 모든 표본에서 완료됐다.
Corpus 테스트의 replay는 각 τ 전이 탐색당 **최대 256개 서로 다른 marking**을 허용했다.

| 고유 로그 | 분석 cases / events | Replay 완료 / 제한 (256) |
| --- | ---: | ---: |
| UCI labour | 25 / 1,392 | 25 / 0 |
| UCI weekends | 10 / 488 | 10 / 0 |
| HH102 labour | 18 / 1,152 | 18 / 0 |
| HH102 weekends | 7 / 420 | **0 / 7** |
| HH104 labour | 32 / 3,116 | 32 / 0 |
| HH104 weekends | 18 / 1,728 | 18 / 0 |
| HH110 labour | 21 / 1,390 | 21 / 0 |
| HH110 weekends | 6 / 368 | 6 / 0 |
| Hospital Billing | 32 / 118 | 32 / 0 |

병원의 plain/gzip에서 같은 표본과 결과를 확인했다. 최대 32개 완전한 trace / 4,096개 event라는
규칙으로 선택했으며 trace 중간을 잘라서 쓰지 않는다. 7개 ADL 로그는 이 규칙 안에 전체가 들어가고,
HH104 labour와 병원은 일부 trace만 분석했다.

완료된 replay의 missing/remaining token은 모두 0이었다. **256 한도의 HH102 weekends는 완료
trace가 없어 그 집계의 해석 대상이 없다.** `silent_state_limit`은 모델 부적합이나 최종 marking의
도달 불가능성을 입증하지 않는다. 최초 요약에는 처리된 prefix 길이가 없어 그 실행에서 420개 이벤트
중 몇 개까지 replay했는지는 알 수 없다.

동일한 HH102 weekends 로그·모델에 한해 탐색 상한을 **1,024**로 높여 한 차례 후속 실행했다.
7개 trace / 420개 이벤트를 모두 처리했고, replay **computed**, **완료 7 / 제한 0**,
missing/remaining **0 / 0**, consumed/produced **2,138 / 2,138**, 최종 marking 도달 7건을 확인했다.
실제 최대 탐색 상태 수는 **677**이었다. Replay 구간 10.672초, 전체 실행 10.815초였다.
기존 알고리즘이나 기본 설정은 변경하지 않았다.

따라서 이 사례에서 256 제한은 replay 완료를 확인하기에 부족했다. 1,024라는 상한을 모든 로그의
권장값으로 일반화할 근거는 없다. 기본 활동 기준 결과를 전체 병원 로그의 적합도, 최적 alignment,
일반적인 모델 품질로 확대 해석하지 않는다. classifier별 discovery·replay는 이번 범위에 포함되지 않는다.

## 처리 시간과 증거 파일

이번 단일 실행에서 import 함수 구간은 병원 plain **30.216초**, gzip **29.320초**,
일상생활 gzip은 파일당 **0.013–0.148초**였다. 전체 대조와 discovery·replay가 포함된 pytest 소요 시간과
구분한다. 다른 프로세스가 함께 실행되는 환경의 단일 관측값이므로 일반적인 성능 비교나 SLA가 아니다.
파일별 최대 메모리 사용량은 측정하지 않았으므로 **알 수 없음**이다.

주요 증거는 `.artifacts/xes-corpus-2026-09-13/`에 보관한다.

- `pytest.xml`, `pytest-output.txt`: 실데이터 테스트 실행 결과.
- `event-log-regression.xml`, `event-log-regression-output.txt`: 기존 92개 회귀 테스트.
- `pix/*.json`: 파일별 import, 전체 보존 대조, profile, 분석 표본, replay 상태.
- `native-read/summary.json`: PIX와 독립적인 원본 XML 전체 집계.
- `native-read/hh104-work-classifier.json`: 4,200개 이벤트의 `work` 열 전체 대조.
- `native-read/executed-command.txt`: 실제 수행한 기본 XML 집계 명령.
- `replay-followup/run_replay_1024.py`, `replay-followup/replay_1024.json`: 1,024 상한 후속 실행.
- `runtime/provenance.json`: 공식 배포 출처, hash, 서명, 실행 환경.

별도 `tools/inspect_xes_corpus.ps1`은 여전히 실행하지 않았다. 위 native-read는 실제 실행한
독립 XML 집계 명령의 결과이며, 미실행 스크립트의 결과로 간주하지 않는다.

판단의 유효 범위는 **2026-09-13의 기록된 소스·데이터 hash와 실행 조건**이다. 같은 입력에서
원본 대조 불일치가 재현되면 해당 보존 판단을 철회한다. 이 범위에서 전체 import·원본 보존과
명시한 분석 표본의 replay 완료를 확인했다.
